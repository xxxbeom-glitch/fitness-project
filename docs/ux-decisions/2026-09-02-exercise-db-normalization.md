# Exercise DB Normalization — 2026-09-02

**Status:** CONFIRMED
**Scope:** G Fit 구매 운동 에셋 / metadata 정규화 기준

이 문서는 Product Owner가 승인한 운동 DB 정리 기준을 기록한다. 대상은 현재 구매한 exercise asset / metadata이며, 외부 앱의 운동 DB를 합치는 작업을 뜻하지 않는다.

## 1. Exercise identity

운동 기록은 실제로 비교 가능한 수행끼리만 같은 기록으로 묶는다.

### 장비가 다르면 별도 운동

예:

- 벤치프레스
- 덤벨 벤치프레스
- 스미스 머신 벤치프레스
- 체스트 프레스 머신

장비가 달라지면 이전 kg / 횟수 / PR을 서로 섞지 않는다.

### 각도 / 주요 자세가 다르면 별도 운동

예:

- 벤치프레스
- 인클라인 벤치프레스
- 디클라인 벤치프레스
- 인클라인 덤벨 벤치프레스

기본 exercise identity는 최소한 `동작 + 장비 + 각도/주요 자세`를 구분할 수 있어야 한다.

### 그립은 선택적인 하위 기록

그립 때문에 검색 목록을 무조건 늘리지 않는다.

- 그립을 구분하지 않는 사용자는 기본 운동 기록만 사용 가능
- 필요한 사용자만 대표 그립을 선택해 별도 kg / 횟수 / PR 이력을 사용
- 기본 기록과 그립별 기록은 서로 섞지 않음
- 기존 기본 기록을 나중에 특정 그립으로 자동 재분류하지 않음

## 2. 사용자 표시명

한국어 표시명은 국내 헬스장에서 자연스럽게 통하는 이름을 우선한다.

예:

- `Bench Press + Barbell + Flat` → `벤치프레스`
- `Bench Press + Dumbbell + Flat` → `덤벨 벤치프레스`
- `Bench Press + Smith Machine + Flat` → `스미스 머신 벤치프레스`
- `Bench Press + Barbell + Incline` → `인클라인 벤치프레스`
- `Bench Press + Dumbbell + Incline` → `인클라인 덤벨 벤치프레스`

구매 원본 영문명은 삭제하지 않고 원본 추적 및 검색용 metadata로 보존한다.

## 3. 구매 DB 중복 통합 — APPROVED

구매 에셋 안에서 이름만 다르지만 실제 수행이 같은 항목이 발견되면 하나의 G Fit 운동으로 통합한다.

### 같은 운동으로 통합

다음 핵심 조건이 같으면 같은 운동 후보로 본다.

- 기본 동작
- 장비
- 각도 / 주요 자세
- 한쪽 / 양쪽 수행 방식처럼 기록 의미를 바꾸는 주요 수행 방식

예를 들어 `One Arm Dumbbell Row`, `Single Arm Dumbbell Row`, `Dumbbell Row Unilateral`이 실제 이미지와 수행 방식까지 동일한 원암 덤벨 로우를 가리킨다면 G Fit에서는 `원암 덤벨 로우` 하나로 통합한다.

통합된 원본 이름은 버리지 않고 alias / 검색어 / source metadata로 보존한다.

### 별도 운동으로 유지

이름이 비슷해도 다음 중 하나라도 기록 의미를 바꿀 정도로 다르면 별도 운동으로 유지한다.

- 장비
- 각도 / 주요 자세
- 한쪽 / 양쪽 수행 방식
- 동작 자체

예:

- 덤벨 로우 ↔ 원암 덤벨 로우
- 벤치프레스 ↔ 인클라인 벤치프레스
- 벤치프레스 ↔ 덤벨 벤치프레스

단순한 이름 차이만으로 합치거나 나누지 않는다. 구매 metadata 이름뿐 아니라 실제 운동 이미지 / 수행 내용을 함께 확인한다.

## 4. 브랜드 / 제조사 머신

MVP 기본 운동 DB에서는 Hammer Strength / Cybex 등 제조사·브랜드별 머신 목록을 별도로 운영하지 않는다.

특정 브랜드/모델 머신을 별도로 추적하고 싶은 사용자는 `직접 만든 운동`으로 기록할 수 있다. 제조사 DB 확장은 실제 수요가 확인된 뒤 재검토한다.

## 5. 운동 부위 분류 — APPROVED

운동을 찾고 추가할 때는 접근성을 위해 큰 부위를 먼저 보여주고, DB와 분석에서는 세부 근육 정보를 별도로 유지한다.

### 사용자에게 먼저 보이는 큰 부위

기본 부위 필터 / 직접 만든 운동의 1차 분류는 다음 수준으로 단순하게 둔다.

- 가슴
- 등
- 어깨
- 팔
- 하체
- 코어
- 전신
- 기타

큰 부위는 사용자가 운동을 빠르게 찾거나 직접 만든 운동을 분류하기 위한 UI 카테고리다. 이것만을 실제 세부 근육 데이터로 간주하지 않는다.

### 세부 근육은 내부 데이터로 유지

기본 운동 DB에는 가능한 경우 실제 주요 근육과 보조 근육을 더 세밀하게 저장한다.

예:

- 랫풀다운 → 큰 부위 `등`, 주요 근육 `광배근`
- 레그 익스텐션 → 큰 부위 `하체`, 주요 근육 `대퇴사두근`
- 루마니안 데드리프트 → 큰 부위 `하체`, 주요 근육 `햄스트링 / 둔근`

세부 근육은 필요할 때 2차 필터, 운동 상세, 분석 화면에서 활용한다.

운동 검색 결과에서는 상세 화면에 들어가지 않아도 운동을 빠르게 구분할 수 있도록 **장비 + 주요 근육** 정도를 작은 보조정보로 노출할 수 있다.

예:

- `랫풀다운` → `케이블 · 광배근`
- `시티드 케이블 로우` → `케이블 · 등 상부`

운동 상세에서는 주요 근육과 보조 근육을 더 명확하게 확인할 수 있게 한다. 즉 큰 부위는 찾기용 분류이고, 주요 근육은 목록에서도 빠른 판단을 돕는 정보이며, 주요/보조 근육 전체는 상세와 분석에서 더 깊게 사용한다.

### 직접 만든 운동

사용자는 직접 만든 운동을 만들 때 큰 부위까지만 선택해도 완료할 수 있다.

기본 입력:

- 운동 이름 — 필수
- 장비 — 필수
- 큰 부위 — 필수
- 기록 방식 — 필수
- 세부 주요 근육 — 선택
- 보조 근육 — 선택

사용자가 `등`만 선택했다고 해서 G Fit이 임의로 `광배근` 같은 세부 근육을 자동 확정하지 않는다. 세부 근육을 지정하지 않았다면 내부 데이터도 `세부 근육 미지정` 상태로 남긴다.

즉 기본 DB는 가능한 범위에서 세밀하게 정리하고, 사용자 직접 추가는 큰 부위만으로도 빠르게 만들 수 있게 한다.

## 6. 실제 구매 metadata 분류 상태

다음 단계에서 각 구매 항목을 아래 상태 중 하나로 분류한다.

- `유지`: 현재 항목을 G Fit 기본 운동으로 사용
- `이름 변경`: 운동은 유지하되 국내 대표명으로 변경
- `중복 통합`: 같은 실제 운동의 다른 원본 항목과 하나로 통합
- `별도 유지`: 비슷해 보여도 장비 / 각도 / 주요 자세 / 수행 방식 차이 때문에 별도 기록 유지
- `1차 제외`: MVP 웨이트 기록 핵심 범위에서 우선 제외

실제 분류는 metadata 이름만으로 확정하지 않고 가능한 경우 구매 에셋 이미지 / 수행 내용까지 함께 검수한다.
