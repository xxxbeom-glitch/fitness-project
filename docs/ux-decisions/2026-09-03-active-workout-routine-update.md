# Active Workout Routine Update Flow — 2026-09-03

**Status:** PO APPROVED
**Scope:** 운동 진행 중 루틴 구성 변경, 운동 순서 변경, 운동 종료 시 루틴 업데이트 확인

## Decision

Active Workout의 운동 목록은 **강제 수행 순서가 아니다.** 사용자는 원하는 운동부터 진행할 수 있으며, 루틴에 있는 운동을 오늘 수행하지 않았다고 해서 별도의 `건너뛰기` 상태를 만들거나 삭제할 필요가 없다.

- 어떤 운동부터 시작해도 됨
- 실제 수행 순서가 루틴 표시 순서와 달라도 루틴 변경으로 보지 않음
- 오늘 수행하지 않은 운동은 그냥 미수행 상태로 남음
- 미수행했다는 이유만으로 루틴에서 제거하지 않음

## Exercise reorder — PO APPROVED

사용자가 `운동 순서 변경` 화면에서 운동 카드를 직접 드래그해 **목록의 저장 순서 자체를 변경한 경우에는 자동 저장**한다.

예:

`벤치프레스 → 숄더프레스 → 랫풀다운`

을 사용자가 명시적으로

`랫풀다운 → 벤치프레스 → 숄더프레스`

로 재정렬하면, 그 순서는 별도의 종료 시 확인 없이 해당 루틴의 새 표시 순서로 바로 저장한다.

- Figma `421_Exercise_Reorder`는 유지한다.
- 명시적 drag reorder 완료 → 루틴 순서 자동 저장.
- 순서 변경에 대해 `오늘만 적용 / 루틴 업데이트`를 다시 묻지 않는다.
- 반대로 목록을 재정렬하지 않고 사용자가 3번째 운동을 먼저 수행한 것처럼 **실제 수행 순서만 달라진 경우에는 저장 순서를 바꾸지 않는다.**
- 따라서 `실제 수행 순서`와 `사용자가 명시적으로 편집한 루틴 표시 순서`를 구분한다.

## Exercise removal

`운동 삭제`는 오늘만 하지 않는 의미가 아니라 **앞으로 이 루틴에서 해당 운동을 빼려는 구조 변경**에 사용한다.

운동 중 해당 운동을 이미 일부 수행했더라도 오늘 완료한 세트 기록은 보존한다. 루틴 업데이트를 확정하면 다음부터 루틴 구성에서만 제거된다.

## Structural changes that can update the routine

다음은 운동 종료 시 루틴 반영 여부를 확인하는 구조 변경으로 본다.

- 운동 추가
- 운동 삭제
- 세트 추가
- 세트 삭제
- 손잡이가 다른 새 운동 카드 추가 등 카드 구성 변경

단, **명시적인 운동 순서 변경은 예외적으로 즉시 자동 저장**하므로 종료 시 위 확인 대상에 다시 포함하지 않는다.

반대로 다음은 루틴 구조 변경으로 보지 않는다.

- 실제 운동 수행 순서
- 오늘 일부 운동을 수행하지 않음
- kg 변경
- 횟수 변경
- 오늘 실제로 완료한 세트 결과 자체

## End-of-workout confirmation

운동 종료 시 위 구조 변경이 있었다면 변경 상세를 길게 나열하지 않고 **변경 종류와 개수만 간단히 요약**한다.

예:

`운동 추가 2개 · 운동 삭제 1개 · 세트 추가 1개`

그 다음 한 번만 루틴 반영 여부를 묻는다.

- `오늘만 적용`
- `루틴 업데이트`

`오늘만 적용`을 선택해도 오늘 운동 기록은 그대로 저장한다. `루틴 업데이트`를 선택하면 오늘의 구조 변경을 이후 루틴에 반영한다.

루틴 구조 변경이 없다면 별도의 업데이트 질문 없이 운동 종료 흐름으로 바로 진행한다.

운동 순서 변경은 앞서 정의한 대로 이미 자동 저장되므로 이 확인창에서 다시 묻지 않는다.

## UX principle

운동 중에는 사용자가 기록에 집중하도록 한다. `다른 운동 먼저`, `오늘 건너뛰기` 같은 별도 상태/UI는 두지 않는다.

사용자는 어떤 운동이든 바로 수행할 수 있고, 목록 자체의 순서를 바꾸고 싶을 때만 `운동 순서 변경`을 사용한다. 명시적 순서 편집은 자동 저장하며, 단순한 실제 수행 순서 차이는 루틴 변경으로 취급하지 않는다.

## Implementation note
