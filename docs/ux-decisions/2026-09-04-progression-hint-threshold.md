# Progression Hint Threshold — 2026-09-04

**Status:** PO APPROVED — MVP v1, adjustable after product data / user feedback
**Scope:** 운동 완료 화면의 `다음 운동 힌트`에서 일반 weight/reps 운동의 증량 힌트를 언제 노출할지 결정

## Decision

MVP의 일반 증량 힌트는 달력 기간이 아니라 **해당 루틴 안에서 같은 운동을 실제로 수행한 최근 기록**을 기준으로 판단한다.

기본 관찰창:

- 같은 루틴의 같은 운동
- 같은 중량
- 최근 5회 수행 기록
- 그중 4회 이상이 성공
- 가장 최근 수행도 성공

위 조건을 만족하면 운동 완료 화면에서 다음과 같은 의미의 힌트를 보여줄 수 있다.

> `다음 운동에서 중량을 한 단계 올려봐도 좋아요.`

강제 처방이 아니라 사용자 판단을 돕는 보수적인 힌트다.

## Success definition

루틴에 정의된 목표 반복 범위가 예를 들어 `3세트 × 8~12회`라면 한 번의 성공 기록은 다음을 모두 만족해야 한다.

- 해당 운동의 예정 세트를 모두 완료 체크
- 같은 기준 중량으로 수행
- 모든 예정 세트에서 목표 반복 범위의 상단값까지 달성

예:

- `80kg · 12 / 12 / 12` → 성공
- `80kg · 12 / 12 / 11` → 실패
- `80kg · 12 / 12 / 12`지만 한 세트가 최종 미완료 체크 → 실패

최근 5회가 다음과 같다면:

- 성공
- 성공
- 실패
- 성공
- 성공(가장 최근)

→ `최근 5회 중 4회 성공 + 가장 최근 성공`이므로 증량 힌트 후보가 된다.

## Why 5 records / 4 successes

`2회 연속 성공`은 사용자에 따라 너무 짧고, 일시적으로 컨디션이 좋았던 두 번만으로도 반복적으로 증량 힌트가 나올 수 있다.

반대로 `4~5회 연속 성공`만 요구하면 한 번의 컨디션 저하로 관찰이 전부 초기화되는 문제가 있다.

따라서 MVP는 **최근 5회 중 4회**를 관찰창으로 사용해 한 번의 흔들림은 허용하되, 짧은 성공 두 번만으로 바로 증량을 권하지 않는다.

이 `4/5`는 모든 사용자에게 적용되는 생리학적 절대 법칙이 아니라 **MVP 제품 임계값**이다. 실제 사용 데이터와 피드백에 따라 후속 버전에서 조정할 수 있다.

## Time / calendar rule

- `2주가 지남`, `7일이 지남` 같은 달력 기간 자체는 증량 조건으로 사용하지 않는다.
- 주 1회 수행 사용자와 주 3회 수행 사용자를 같은 기간 기준으로 묶지 않는다.
- 실제 수행 기록 5회가 쌓였는지를 본다.

장기간 운동 공백 후 기존 관찰 기록을 어떻게 취급할지는 이번 MVP 임계값에서 별도 숫자로 확정하지 않는다. 실제 필요가 확인되면 후속 결정으로 다룬다.

## Reset / re-observation

다음 경우에는 기존 중량의 관찰을 이어서 증량 힌트를 만들지 않고 새 기준으로 다시 관찰한다.

- 사용자가 힌트 전에 스스로 중량을 올림
- 사용자가 중량을 낮춰 새 기준 중량으로 운동을 진행
- 해당 루틴에서 운동의 예정 세트 수가 변경됨
- 해당 루틴에서 목표 반복 범위가 변경됨

즉 사용자가 이미 새로운 중량을 선택했다면 뒤늦게 이전 중량을 기준으로 `올려도 좋아요`라고 말하지 않는다.

## Routine context

판단 단위는 **같은 루틴의 같은 운동**이다.

같은 운동이라도 다른 루틴에서 세트 수 / 목표 반복 범위 / 운동 목적이 다를 수 있으므로 서로 다른 루틴의 기록을 임의로 섞어 증량 힌트를 만들지 않는다.

운동 identity 자체와 과거 기록 보존은 그대로 유지하되, `이 루틴에서 증량해도 되는가`라는 힌트의 관찰 컨텍스트는 루틴별로 분리한다.

## Amount of increase

MVP에서는 `+2.5kg`, `+5kg`, `+5%`처럼 정확한 증량 폭을 자동 처방하지 않는다.

기구 / 원판 / 머신 스택마다 가능한 증량 단위가 다르고, 사용자의 컨디션과 수행 여유도까지 MVP에서 충분히 알 수 없기 때문이다.

기본 카피는 `한 단계 올려봐도 좋아요`, `중량을 조금 올려볼 만해요`처럼 방향만 제시한다.

## Exclusions

이 일반 규칙은 우선 `weight_reps` 계열의 일반 중량 운동에 적용한다.

다음은 동일 규칙에서 제외하고 별도 progression semantics가 필요하다.

- `assisted_weight_reps`
- bodyweight 계열
- duration 계열
- distance 계열
- 기타 일반적인 `더 높은 kg = 더 강한 부하` 의미가 아닌 기록 방식

특히 assisted 운동은 기존 결정대로 보조 kg가 낮아지는 방향이 일반 중량 증가와 반대이므로 이 규칙을 적용하지 않는다.

## Presentation principle

- 힌트는 강제 명령이 아니다.
- `반드시 올리세요`보다 `한 단계 올려봐도 좋아요` 같은 표현을 사용한다.
- 사용자가 직접 중량을 조절할 최종 권한을 가진다.
- 같은 힌트를 사용자가 무시했다는 이유만으로 과도하게 반복 노출하는 세부 빈도 정책은 필요 시 후속 UX에서 조정한다.
